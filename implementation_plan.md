# Batch Orchestrator Implementation Plan

This plan outlines the architecture and implementation steps for the missing Batch Orchestrator. The orchestrator is the plain Python layer that manages data ingestion, deterministic fast-path matching, fuzzy clustering, LangGraph invocation, and global ledger safety.

## Key Clarifications from Feedback

> [!TIP]
> **Resolved Answers to Open Questions:**
> 1. **Data Ingestion Format**: `IngestBatch` will strictly mirror the CSV outputs generated by the Step 2 synthetic data generator (one CSV per table). We will inspect the actual generator structure/files before assuming the final Pydantic schemas. 
> 2. **Concurrency**: Bounded concurrency will be implemented, capped tightly at **2 to 3 concurrent in-flight clusters** using an `asyncio.Semaphore`. This protects the 30 RPM Groq rate-limit budget and prevents cascading 429s.
> 3. **Sync vs. Async Consistency**: We have confirmed that the existing graph nodes and tools (`app.agent.tools.py`) already use `async def` and `async_session`. The orchestrator can safely use `asyncio.gather` and native async SQLAlchemy without blocking the event loop or needing `run_in_executor`.
> 4. **Exhausted Models Race Condition**: The `exhausted_models` flag on `ReconciliationRun` (JSONB) will be updated using a Postgres-level atomic append (e.g. `UPDATE reconciliation_runs SET exhausted_models = coalesce(exhausted_models, '[]'::jsonb) || '["model"]'::jsonb WHERE ...`) to prevent read-modify-write clobbering across concurrent clusters.
> 5. **`business_days_between`**: The `app/synthetic/calendar.py` file does not currently exist. We will implement this calendar utility in `app/utils/calendar.py` and fix the dangling import in `app/agent/nodes/resolution.py`.
> 6. **Environment Setup**: A background task has been spawned to install Python 3.11 into the environment so we can actively run, test, and verify these high-risk async operations as we build them.

## Proposed Changes

We will create a new package `app/orchestrator` to house the deterministic pipeline steps defined in the lock-in plan.

### app/orchestrator

#### [NEW] [ingestion.py](file:///d:/Downloads/temp-main/app/orchestrator/ingestion.py)
- **`CanonicalUtrExtractor`**: Regex-based utility to strip CBS prefixes/suffixes from bank narrations.
- **`IngestBatch`**: 
  - Computes the SHA-256 checksum of the source data.
  - Queries `ReconciliationRun` to prevent duplicate batch processing.
  - Normalizes timestamps to UTC.

#### [NEW] [matching.py](file:///d:/Downloads/temp-main/app/orchestrator/matching.py)
- **`ExactIdJoin`**:
  - **Hop 1**: Joins Orders/Refunds/Disputes with Settlements. Verifies `gross - refunds - disputes = net + fee + tax`. 
  - **Hop 2**: Joins Settlements with BankTxns on normalized UTR. Verifies `net = credit - bank_charges`.
  - Promotes successful matches directly to `MatchGroup`/`MatchAllocation`.
  - Demotes failed arithmetic to clustering with `original_tier_hint = "exact_id_conservation_failed"`.

#### [NEW] [clustering.py](file:///d:/Downloads/temp-main/app/orchestrator/clustering.py)
- **`FuzzyScore`**: Uses `rapidfuzz` to calculate similarity scores between unmatched entities.
- **`ClusterCandidates`**:
  - Filters pairs based on score thresholds and date windows.
  - Uses Union-Find (disjoint-set) partitioning to group candidates into exclusively owned `CandidateCluster` objects.
  - Enforces a hard cap of 8 candidates per cluster (sub-partitioning if needed).

#### [NEW] [persistence.py](file:///d:/Downloads/temp-main/app/orchestrator/persistence.py)
- **`PersistMatchOrException`**:
  - Handles writing `MatchGroup`, `MatchAllocation`, and `ExceptionStaging`.
  - Implements the safety guard: Catches `IntegrityError` (UniqueViolation on `entity_type`, `entity_id`), rolls back, and reroutes orphaned entities to `CategorizeException(ESCALATED_UNRESOLVED)`.

#### [NEW] [safety.py](file:///d:/Downloads/temp-main/app/orchestrator/safety.py)
- **`BatchSafetyChecks`**: Evaluates the global conservation equation across all processed rows in the batch.
- **`UnaccountedLedgerLeak`**: Attributes any non-zero global residual to this exception category.
- **`ReportMatchRateThroughput`**: Finalizes the `ReconciliationRun` record with `match_rate`, `processing_ms`, and `ledger_leak_variance_paise`.

#### [NEW] [pipeline.py](file:///d:/Downloads/temp-main/app/orchestrator/pipeline.py)
- **`run_batch_pipeline`**: The main entry point that coordinates the entire flow:
  1. Ingest & Deduplicate
  2. Hop 1 & Hop 2 Exact Matches
  3. Fuzzy Scoring & Clustering
  4. Bounded concurrent invocation of `app.agent.graph.run_cluster` for ambiguous clusters.
  5. Persistence & Safety Checks.
